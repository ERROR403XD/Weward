# Weward 投递任务扩展使用说明

日期：2026-11-08。所属项目：Weward。仓库：ERROR403XD/Weward。

本次增加自定义请求头、multipart/form-data、成功响应条件及按批次手动重试。既有任务无需修改，默认仍以 ZIP 直传，并校验 HTTP 2xx、ok=true、匹配的 batch_id 和非空 receipt_id。

## 配置一个表单投递任务

1. 打开「投递任务」，新建或编辑任务，填写接收地址、计划和群范围。
2. 将「请求格式」选为 `multipart/form-data`。现有 ZIP 放在 `files` 字段，文件名为 `weward-<batch_id>.zip`；可填写 `text`，留空则不发送该文本字段。
3. 在「自定义请求头」添加 `Authorization`，值填写外部接口要求的内容，例如 `Bearer example-token`。请求头值以密码框显示，保存后不回显。编辑时留空保留原值，填新值替换，移除行删除。
4. 将「判断方式」选为「自定义响应条件」。例如：成功状态码 `2xx`，JSON 字段 `outcome`，预期值 `"submitted"`。字符串必须带双引号，因为预期值使用 JSON 格式。
5. 保存并启用任务，点击「发送」或等待计划执行。

该示例只有在 HTTP 状态为 200–299 且响应 JSON 中 outcome 等于 submitted 时才算成功。自定义模式不再要求旧协议的 ok、batch_id、receipt_id。外部仍需按 Idempotency-Key 去重并确认已可靠接收。

成功状态码也可填写 `200,202`；JSON 字段支持 `data.outcome` 这样的嵌套对象路径。缺失字段、错误值、HTTP 错误、超时或无效 JSON 均保持批次待重试。布尔 true 与数字 1 不相等，字段缺失与值为 null 也不同。

自定义模式下，JSON 字段留空会只判断状态码，允许空正文。只有外部接口确实用状态码确认接收时才使用此设置。默认回执模式仍拒绝空正文。成功响应正文统一限制为 64 KiB。

## 回执与重试

在「投递历史 → 详情」查看结果、回执、生成时的接收地址及成功条件，也可下载实际 ZIP。自定义模式保存 HTTP 状态和响应内容；默认模式保留原回执格式。界面和 API 中会隐藏请求头值，并对响应或错误中回显的敏感值脱敏。数据库保留用于投递的原始请求头和原始成功回执。

失败会自动退避重试，最长间隔一小时。也可以在任务列表点「重试」，或在历史详情点「立即重试」。手动重试需要任务启用；已完成批次不能再次重试，也不会因旧页面操作而触发新批次。

回执保存、批次标记已发送和游标推进在同一数据库事务完成；任何一步失败都不会部分确认。成功/失败通知继续独立排队，通知网络故障不阻塞投递。

## 配置修改的生效范围

每个批次生成时固定 ZIP、接收地址、请求头、投递方式、text、成功条件和 Idempotency-Key。multipart 的 boundary 与完整请求正文一起保存。修改任务、重启、自动重试或手动重试都不会改写已生成批次。

编辑任务只影响之后生成的批次，包括当前轮尚未生成的后续分包。旧版允许修改待重试批次的地址；此次为了保证同一批次请求参数不变，取消这一行为。

如果已生成批次的地址或凭据需要更换，先暂停旧任务并核对外部是否已经接收，再创建新任务。新任务游标独立：包含历史可能重复发送，选择仅创建后收到的消息则跳过既有记录，应按需要选择。

## 升级与回退

数据库会自动增加配置和请求快照列，既有任务、回执、ZIP 和游标保持兼容。multipart 保存完整请求正文，其中包含 ZIP 副本，因此会比直传增加磁盘占用。Content-Type、Content-Length、Idempotency-Key 和 X-Weward-* 等协议头不能被自定义配置覆盖。

升级前按项目部署规范保存数据库备份。仅需更新 receiver；本次不要求重建 collector 或重新登录微信。回退时先暂停任务并等待正在进行的请求结束，恢复旧程序及升级前数据库备份。旧程序不认识新增配置，不能直接继续处理含新功能任务的数据库。外部已经接收的数据无法通过本地回退撤回。

本次 `python3 -m unittest discover -s tests -v` 共 74 项测试通过，比原基线增加 11 项。验证使用临时数据库和模拟 HTTP 接口，覆盖旧库迁移、ZIP/multipart 真实 HTTP 发送、敏感值脱敏、条件判断、事务回滚、按批次重试及配置修改和重启后的请求一致性。浏览器验证覆盖配置、错误提示、密码框、回执与手动重试，以及 1440、768、390、320 像素布局。实际外部服务的鉴权和接收语义仍需按其接口验收；本次未部署运行服务。
